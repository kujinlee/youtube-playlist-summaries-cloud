Owner 2026-11-05 13:54: a goal is named for its **objective** — the purpose that groups its threads — and it often follows a
feature (token management, dev-speed optimisation, memory matching). Features come from a need of the design or the process,
and a person may not see every arising goal, so **I propose the goal name; the owner picks it or counter-proposes.** A name is
good when it says the purpose and fits the threads under it.

**Why:** that morning 8 of 8 in-flight entries showed "no goal" — the tree refuses to GUESS a goal from a name (correct), and
I had read the grammar's "a goal opens with the owner's quoted words" as meaning I could not open one. The owner rejected that.

**How to apply:** when adding work (`session-state.py --add`) or a thread with no fitting `## GOAL`, propose one by objective
on a selection card (A = my recommended name). Until backlog #514 builds the "proposed goal" grammar, a new goal still needs
a `>` request line — use the owner's card answer as that line. Related: [[parallel-threads-need-a-thread-map]].
