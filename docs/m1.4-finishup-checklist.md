- [ ] **B3 — serve-doc money re-run. ❌ FAILED 2026-08-11 — the gate found a real defect. DO NOT TICK.**
      **FAILS IF:** the error is classified as *absent* (a 404-shaped `statusCode`, or none at all)
      **OR** `spend_ledger` moves by more than the single reservation the first serve already made.
      **VERIFIED AGAINST: v6 / `d9cdcb8`** (2026-08-11), hosted staging `neeufoxdbgbpkjukzzuc`, with the
      spend authorised by the user. **BOTH clauses tripped.**
      - phase 1 (healthy): `resolve → ok`, 7.9s, **real Gemini**. spend **0 → 6¢**, `attempt_count` 0 → 1,
        envelope written. Keep-settle applied.
      - phase 2 (`drop policy artifacts_owner_rw`, the same real fault B2 used): probe classified the
        model read **`absent`** → the money guard never fired → reserve → **a second real Gemini call**
        → spend **6 → 12¢**, `attempt_count` 1 → 2, then the write threw
        `new row violates row-level security policy`. The lease was force-expired first, so
        single-flight cannot have masked the charge.
      - phase 3 (restored): `resolve → ok` in 49ms from cache, spend delta **0¢**. Heals.
      **ROOT CAUSE — measured, not inferred.** The raw Storage error is byte-identical in both cases:
      `{"message":"Object not found","status":400,"statusCode":"404"}` for an object that exists but is
      policy-denied, and for one that genuinely does not exist. RLS makes the row invisible, so Supabase
      reports 404. `tryGet` discriminates on `statusCode === '404'`
      (`lib/storage/supabase/supabase-blob-store.ts:49`), so an RLS denial is classified *absent*.
      **The defect:** the serve-path money guard treats `tryGet → absent` as proof of absence on a store
      that declares `readonly provesAbsence = false` (`supabase-blob-store.ts:10`). The **sync** path
      consults that flag correctly (`lib/cloud-sync/sync-run.ts:697`) — which is the actual reason B2
      passed. `serve-doc.ts`'s own comment claims `tryGet` distinguishes
      *"5xx, timeout, RLS denial, transport error"*; it distinguishes three of the four, and misses the
      one it names first.
      **SCOPE OF THIS VERDICT, stated precisely — one fault class was exercised, not two.**
      - **RLS denial → FAILS** (measured above). 404-shaped, so classified *absent*, so re-charged.
      - **A real 5xx / timeout / transport error → would PASS, and was NOT exercised.** Those do not
        carry `statusCode '404'`, so `tryGet` returns *unreadable* and the guard fires as designed.
        Producing a genuine 5xx from Supabase on demand is not something this run could arrange.
      The roadmap's older copy of this item asked specifically to *"confirm a real **5xx** carries a
      non-404 `statusCode`"* — a narrower claim than the checklist's *"a real blob-read failure"*, and
      one that is probably true. The FAIL stands because the gate as written is failed by a real
      failure class; but the guard is not useless, it is **narrower than its own comment claims**.
      **Fix lead (not started — needs its own slice):** `serve_model_charge.attempt_count >= 1` already
      records that a model was successfully written for this `doc_key`, so a later *absent* read on that
      doc is corroborated-suspicious and should be treated as unreadable rather than re-charged.
      **⚠ CORRECTION OWED TO B2 (below):** its recorded rationale — *"makes owner reads fail with a
      permission error rather than a 404"* — is measured **false**. B2's PASS stands; the sentence
      explaining why does not.

      **IT WAS A CODE CHANGE, AND IT OVERTURNED A SPECIFIED, TESTED RULE.** `app/s/[token]/route.ts`
      called `readFreshMagazineModel`, whose `isFresh` requires `generatorVersion === GENERATOR_VERSION`;

      doc its owner never revisits stayed broken after every version bump. Now `readTitleStableModel`

      **What tolerating actually costs — corrected by the adversarial review, which caught this
      claim overstated in its first draft.** The first version of this entry said zod's `.strict()`
      meant "a model whose SHAPE changed still fails closed". **That is only shallowly true.**

      the accepted cost of the decision, not a guarantee against it.
