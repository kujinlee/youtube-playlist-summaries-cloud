4. The ffmpeg question

You asked whether we know the root cause. Not proven. Here is what is measured and what is not.

MeasuredHow
The step either finishes in 16–19 s or exceeds its 150 s download limit on all 3 tries.step timings from 3 good runs; the failure messages
4 of 14 verify attempts failed this way by early afternoon, and at least 3 more after.job/step results per attempt via the GitHub API
It is a crawl, not a hang: each try fetched a few small packages from azure.archive.ubuntu.com (amd64v3 pool), stalled on a large one (libcodec2, 9 MB), and the next try resumed from there.apt's own output in a failed run's log
apt-get update always succeeds; only the package download fails.same log

Inferred, not verified: the Azure mirror serves the new amd64v3 pool poorly at times. A per-runner network problem would look the same. Either way it is outside this repo.

The fix (option A): keep a copy of the downloaded packages in GitHub's cache. The cache key is a hash of the exact package list apt prints for that run, so a changed list is never served stale. apt skips a file already in its cache, so a cache hit downloads nothing.

⚠ Correction (14:15, found by review, executed in an Ubuntu container). This page, the PR and the dashboard entry said apt checks a cached file against the checksum in its signed index. It does not: apt accepted a fabricated package of the right size, and installed it. So the cache must check each restored file's SHA256 against the signed index before handing it to apt. The page also said a failure in the new steps leaves the install untouched; also false — a hang in the key step, or a restore error, can make GitHub skip the install. Both are being fixed before merge; neither has reached master.

How it will be proven: the first run should miss and save; a later run must log ffmpeg cache: restored N package(s) with a short step. The first half was seen (all four new steps succeeded on run 40397292029's job). ⟳ 14:15 — the second half was seen too: run 40400167030 hit the same key, logged ffmpeg cache: restored 81 package(s) and Need to get 0 B/66.4 MB, and skipped the save (read from the run log by the Claude review half). The cache works; the corrections above must still land before it merges.
