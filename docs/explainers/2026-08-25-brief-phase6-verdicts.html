Finding 1 · 🔴 Blocking · FILE · STRENGTHENED on re-derivation

Nine findings across four rounds are one architectural choice

The claim. M4 built a fingerprint comparator — does the deployed catalog match a derived manifest? — where the risk is behavioural: does the schema still refuse what it promises to refuse? A fingerprint must enumerate what to compare and be comparable across environments. Every Blocking/High in rounds 4–7 lives in one of those.

MEASURED The size of each instrument, this session:

This is what changed, and it makes the finding sharper

My review supported "the assertion already exists" with keyword counts — which prove nothing about what a block asserts. That was the weakest link, so I opened the file. MEASURED 05_assert.sql:744-759 contains, verbatim:

set local role anon;
  ... execute 'truncate video_artifacts';
  raise exception 'ASSERTION FAILED — anon TRUNCATEd the paid manifest';

and at :728-729, a comment recording it as a measured live hole that the revokes closed: "anon TRUNCATEd the paid manifest to zero rows."

So round 7 did not discover the anon-TRUNCATE gap. It rediscovered it. Someone found it, fixed it, and wrote the assertion — and the assertion has never run, because the file carries zero @RE-RUNNABLE markers. The gate then spent a Blocking finding relearning it, and my proposed fix was to add a column and a written reason to the fingerprint.

Finding 2 · 🟠 High · FILE

Environment-invariance is a self-inflicted obligation

The claim. The digest may only contain properties that agree between a --no-privileges clone and production. That constraint — not any coding error — produced the three worst privilege findings.

MEASURED against production, read-only, tonight:

defacl|public|r|{postgres=arwdDxtm, anon=arwdDxtm, authenticated=arwdDxtm,
                 service_role=arwdDxtm, claude_ro=r}
local roles: anon, authenticated, service_role        (no claude_ro)

READ m4_catalog.py:109-149 documents the workaround at length. The reasoning is correct; the obligation is the problem.

Consequence. r6 B1 — the gate would have argued for rolling back a successful production migration. r7 H1 — a grant to any role outside a four-name tuple is invisible, and production has a fifth. r7 codex B1 — excluding service_role to dodge the environment difference blinded the digest to the one explicit grant the spec makes.

Severity 🟠, not 🔴 — it is the mechanism behind F1's instances rather than an independent failure. What would move it up: if (b) is chosen, it becomes Blocking, because it is then permanent.

Finding 3 · 🟠 High · FILE · NUMBER CORRECTED

A human-audited list of written reasons cannot bear this weight

The claim. check-catalog-coverage.py requires every catalog column to be digested or excluded with a written reason. The design is right — it converts "did I remember?" into "is this reason true?" Then four of the reasons written under it were false.

Corrected on re-derivation

My review said "4 of ~15 … a 27% error rate." MEASURED the real denominator: len(EXCLUDED) == 17. So 4 of 17 = 24%. The conclusion is unchanged; the number I published was not one I had counted.

The architectural point is not that I wrote bad reasons. It is that the load-bearing element is a paragraph of prose per column, with no falsifier — in a repo whose own rule is "state the observation that would make it FAIL." Every other gate here is a script; this one is an essay with a test harness around its index.

Severity 🟠, not 🟡. Two of the four claimed coverage that did not exist, which is the class that produces a green check over a live hole. What would move it down: making that class mechanical — a reason naming another check must be false until that check demonstrably covers the subject.

Why this is not an independent finding

I filed it as F4 in the review. On re-derivation it fails the test the skill sets: it has no separate fix. Nothing is done about "the ratio is bad" that is not already done by F1(a). It is evidence for F1, and filing it separately would create a tracked item whose only closure condition is another item's closure.

Keeping it visible matters, though: it is the most legible symptom. A fingerprint needs a manifest, a generator, a coverage ratchet, a mutation harness and a baseline. An assertion needs a raise exception.

ARGUED The claim that the work was not wasted — the gate found real defects, including the workspaces anon-write hole that would have shipped. That is a judgement, not a measurement.

Finding 5 · 🟡 Medium · FILE (M5, as an ADR)

The service_role question dissolves at M4 and returns at M5

The claim. service_role holds INSERT on video_artifacts but cannot use it — art_slot_kind calls slot_kind(), executable by nobody — in a container, while production's default ACL would let the same INSERT succeed.

Sub-claims, separately:

  • MEASURED container: has_function_privilege('service_role', slot_kind) = false.
  • ARGUED production: the same INSERT succeeds. Derived from the measured default ACL — not executed, and not executable until M4-β, because claude_ro and prod's default privileges cannot be reproduced locally.
  • MEASURED no callers exist, so nothing reaches either path today.

Consequence. Nil at M4. At M5 — whose entire content is moving writers onto generations — a writer developed against the container behaves differently in production.

Severity 🟡, not 🟠. No consumer exists. What would move it up: the first real caller of the generation write path; at that moment it becomes High and possibly Blocking.

Decide while it is cheap

Either the write path is record_artifact only and the direct DML grants are removed, or slot_kind gets an explicit grant and direct DML is supported. Do not leave it environment-dependent. This belongs in an ADR, not in a gate.
