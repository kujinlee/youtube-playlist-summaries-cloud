The rule that decided every placement

Is it a measurement, or is it a decision? A measurement is an observation with a time on it, so a dated historical record is its correct home — and the spec cites it there rather than copying it, which is what portable-practices §26 requires.

A decision is different, and this is the part that was wrong until today: §8's four rejections and §9's five answers were pointed at, not moved. The evidence document's own banner says no decision is cited from it. So the spec was citing a retired file for decisions while forbidding exactly that — and the spec's own falsifier fired on it. They are moved now.

2Why the section numbers have gaps on purpose

The evidence document keeps §1, §4, §5, §6, §7 and skips the rest. That looks untidy and is deliberate: roughly 23 review documents cite this content as §6, by number. Renumbering would have broken every one of those citations silently.

It is also why the old filename still exists. Deleting it would have turned 23 stale citations into 23 dangling ones — so the path survives as a forwarding table whose only job is answering “where did §N go?”

3The citing-sites list — the actual fix, and why prose kept failing

Three rounds, one defect, repeated

Rounds 1, 2 and 3 each found a reader sent to a retired section. Each repair covered only the sites the previous round happened to name, so the next round found a different one. Round 3 called this thrashing and named the cause: no document lists the inbound sites, so every sweep is performed from scratch by hand and each one is incomplete somewhere new.

The tombstone now carries that list — 7 live sites, each with what it cites and whether that is measurement or design, plus ~23 historical ones left untouched as dated testimony.

What is safe to say, and what is not

Safe: the mutation sweep is roughly four fifths of the verify job. That holds across all 34 runs.

Safe: a within-run ratio is far steadier than a duration. Totals vary 1.79× while shares vary 1.13× — as dispersion above 1, 79% against 13%, about six times less variable. That “six times” now states the definition it depends on, because the raw quotient of the two ratios is 1.6× and the two measure different things.

⛔ Not safe: any comparison of one run's duration against another's. And not the old “GitHub is 2× faster than this machine” — it sets CI's whole verify job against the local sweep alone. That retraction had reached one of five places that state it; it now reaches all five.

The four signals, named — because the row above leans on them

They answer one question: is this a seam problem or a logic problem? A seam problem wants an architecture review before more building; a logic problem wants the normal review loop. Spec §2, The escalation half.

#SignalWhat it means in practice
1fixes locally correct but non-terminatingeach repair is right on its own terms, and the findings keep arriving
2each fix ADDS codethe change grows instead of removing the cause
3machinery that manages a problem rather than doing workscaffolding is being built around a defect instead of eliminating it
4two names for one conceptduplicate vocabulary, which shadows a duplicate mechanism
This branch is a live positive for the first two — which is also why calibration is not optional

Round 3's verdict names the class exactly: “a pointer changes and the repair covers only the sites the previous round named.” Three rounds, each fix locally correct, none terminating — signal 1. And each fold answered by adding more prose rather than removing the cause — signal 2. The spec's recorded positive is decision-card-soundness, which hit signal 4 (three synonyms hid a thrashing trigger) and signal 1 (four falsifier designs, each locally correct, none terminating).

⛔ But a signal that fires on real thrashing is only half of what a gate needs. Nobody has checked whether these also stay quiet on branches that converged cleanly. Until that is measured, a script asserting “this is thrashing” could be firing on everything — which is precisely what §3 refuses to allow, and why a negative result there is a result and not a failure.
