Three errors of mine, and what caught each

1 · A regression I wrote into the new renderer

My emphasis rule forbade any asterisk inside the span, which silently dropped emphasis containing bold — live on the backlog page, in row #23. The old backlog renderer gets it free by running bold first; a single left-to-right scan has to step over the ** pair itself. Caught by diffing the new renderer against the old one over all 213 strings — not by reading, and not by the 73 cases that existed at the time.

2 · A spec claim about a mechanism that does not exist

The spec said the new module would be discovered as the 25th guard in the ratchet inventory. It is not, and cannot be: the inventory’s population is glob("check-*.py"), so a file named otherwise never reaches the docstring rule. Caught by running the inventory after adding the enrolling word and seeing it still report 24. That is the right outcome — a renderer is not a guard — but the spec asserted a mechanism that isn’t there.

3 · Blast-radius numbers measured over the wrong population

I fed whole source files through each renderer. Fair for three of the four — but the goals page renders only the one-line Goal: strings. There are 39 of them, containing zero emphasis spans, links, code spans or bold. The spec claimed 145 emphasis spans and 17 links would start rendering there. The truth: the goals page’s output does not change at all. Caught by generating the page and finding 0 <em> where 145 were predicted.

What happens next, and why it is one commit rather than two
