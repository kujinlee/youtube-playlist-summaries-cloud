The decision

Backlog #54, half (a): revoke the default privileges in production

Recommendation: do it. Supabase grants EXECUTE to anon at CREATE FUNCTION time, so today's safety record — 10 anon-callable SECURITY DEFINER functions, 8 guarded by auth.uid(), 2 read as benign — is eight authors independently remembering. The 27th function arrives exposed exactly as the others did.

The strongest argument against It changes production grants, and the live exposure was measured as bounded — no exploitable path found. So it is not urgent. Worse, a default privilege is itself something a later grant can undo silently, which means (a) alone would re-commit the same defect one level up.

The answer to it That objection was exactly right yesterday and is answered today: half (b) shipped. check-anon-exposure.py now enumerates the catalog, fails on any unlisted anon-callable definer function, and re-verifies each allow-list entry's stated reason against the live definition. So a silent later grant is now caught. (a) was unsafe without (b); (b) exists.

Cost One migration, one supabase db push, and a re-run of the ratchet to confirm the number falls. The TRUNCATE baseline of 5 would drop with it.
