1 · What actually happened

PR #345 adopts two sections of an internal study into the project’s standing rules. The study had found that a large share of what reviewers were catching were not faults in the code but claims the author had never checked — an asserted line count that had gone the other way, a file count copied into three further places, “the class is closed” asserted twice over instance fixes.

So the PR adds four author-side rules. The first is: no number unless you measured it in this session.

The repo’s own decision procedure scoped the change as one review round — it is prose-only, and scripts/check-review-decision.py keys that decision on the changed path set rather than on judgement. It took six, and a Phase 6 architecture review in the middle.

The uncomfortable part, first rather than buried. Both High findings in round 1 were the coordinator’s own unverified claims — inside a change whose entire content is rules against unverified claims. One asserted that a practice “caught a Blocking on its first use”; the review document it named says, in a paragraph written to pre-empt exactly that attribution, that the finding rested on a different measurement entirely.

2 · The spine: five fixes, each narrowing to the last shape seen

This is the whole page in two sentences. Five consecutive fixes were each individually correct. Each one narrowed to the form of defect it had just been shown — and the next instance arrived wearing a different spelling.

  1. **34** — bolded digitsA check for surviving wrong numbers matched only the bolded form. Two of three survivors were unbolded.
  2. 34 — any digitsWidened to all digits. Missed the next one entirely, because it was not written in digits.
  3. “the fifteen schema gates” — a number as a wordA count of the repository, spelled in letters, inside the governing rule. Round 4, Blocking.
  4. check-merge-ready.py:52-55 — a line locatorA citation that drifts the moment the file is edited. Replaced with the symbol name.
  5. “Rule 3 twenty lines below” — a document-relative positionSame class again, now measuring the document rather than the repository.
  6. A shape, not a patternRound 4 stopped widening and changed the kind of fix. Round 5 tested it and found the rule bodies clean — no sixth spelling.
Any single fix here looks like diligence. The sequence looks like a wrong instrument. That difference is legible only in aggregate, which is precisely why no individual round caught it and why the repo has a mechanical trigger for the shape rather than relying on someone noticing.

3 · Why a pattern could never terminate this

The obvious repair — “write a check that finds numbers in prose” — is not merely unattractive here. It is already refuted, three times over, with measurements on record.

The repo’s existing rule Qualify every number in prose records the syntactic hunt being tried at every scope that could carry it, and rejected:

ScopeBare #N foundVerdict recorded
all of docs/1,556 of 2,130a gate firing 1,556 times is disabled the same day
added lines on one branch24~90% false positives

And it reproduced again, during this work, on the very section being repaired. A sweep for digits, number-words and positional tokens over that section flagged most of its lines — dates, PR ids, backlog ids, rule numbers, row references, and the word “one” used as a pronoun — against a handful of genuinely repo-tracking expressions.

A syntactic proxy for “is this reference resolvable?” is the wrong instrument; the property is semantic.

The repo had also already written down the terminating move for this exact signature, in a different component: refuse what cannot be classified, rather than widening the pattern. That line existed before this branch started and was not reached for until round four.

4 · What the machinery did — the trigger fired by itself

The project arms a Phase 6 architecture review on thrashing, defined as: two consecutive rounds carrying findings caused by the previous round’s own fix, in one component.

Crucially, that is not a judgement someone makes. Each round’s coordinator document carries a small machine-readable header, and the decision tool computes the verdict from those records:

$ python3 scripts/check-review-decision.py
ARCHITECTURE_REVIEW — thrashing: 'number-populations' carried fix-induced
findings in r2 and r3
  branch=velocity-177  scope=one-round  rounds=3  tree_reviewed=True
Why this design matters more than the verdict. The party whose fixes caused the thrashing is the same party who would otherwise decide whether thrashing occurred. Deriving it from recorded evidence removes that conflict — and makes talking yourself out of it require going back and editing the evidence, which is visible. The repo’s rule adds one line on top: the firing is not to be litigated. That correction was itself bought by an episode where arguing the trigger’s wording cost three rounds of being technically right.

At the end of round 6 the same tool returned STOP — converged — a round saw the merging tree. That output was recorded during the session; it cannot be re-executed now, because the verdict is branch-scoped and the branch was deleted at merge.

5 · The root cause, and why it inverts the usual question

Every Phase 6 review here is obliged to ask: “what did we decide this milestone that isn’t written down?”

The answer was: it was written down. Three days earlier.

CONTEXT.md line 119, added in commit 5ffe6017 on 2026-09-21, after that same glossary was found claiming one number while the live guard printed another:

The number is removed rather than corrected — it had no owner, and this file is inside the corpus it describes, so any figure here is stale at the commit that writes it.

That is a complete, correct, general principle. It is also, operationally, invisible:

QuestionAnswer
Is it an ADR?No. None of the thirteen files under docs/adr/ mentions it
Does any process document point at it?No — though it is restated in a roadmap section, found by round 4
Does any guard detect a newly pinned figure?No
Days between the decision and this thrashing3
The gap is between recorded and findable. A principle whose only homes are a parenthesis inside a glossary entry about something else, and a status line in a roadmap, is a principle nobody writing a number will meet. Three rounds, two reviewers and four repair attempts were spent rediscovering it one instance at a time. Every finding was correct. Every fix was correct. None could terminate.
And the review overstated its own finding. Its first draft said the decision’s only home was that parenthesis. Round 4 found the second home with a search the review had not run — an asserted claim, inside a review about asserted claims. Corrected in place; the narrower statement survives.

6 · The terminating move: a shape, not a wider pattern

Round 4 stopped widening the pattern and changed what kind of thing the fix was. The rule section now declares an invariant over itself:

Scope: this section — its preamble and the bodies of its rules.
Within it, three forms are refused:

  1. a count of anything in this repository, in digits or in words —
     including a count of this section's own contents;
  2. a file:line locator where the name of the symbol, constant or
     comment would serve;
  3. a document-relative position — "twenty lines below".

Everything else stays, including quotations of code and
cross-references by name.

Two refinements came from round 5, and both matter:

  • The enumeration is the test; the prose sentence is only its reason. An earlier draft led with “makes no claim about the repository’s contents”. Read as the criterion, that forbids three expressions the rules actually need — including a verbatim quotation of a guard’s own comment. Worse, the repo’s review method mandates quoting code with a file:line. A criterion that condemns the project’s own standing rule is the wrong criterion.
  • The scope is this section, not the repository. The first version said “a governing rule’s body”, which reads either as this section (no reach) or as every rule in the repo (condemning documents that legitimately cite lines). Widening it is a real question that needs an audit of what it would condemn — filed, not asserted.
Why a shape terminates where a pattern cannot. A pattern has to anticipate every spelling of the defect, and the defect supplies a new spelling each round. A shape says what the text may contain, so there is nothing left to outrun. The preamble’s count of its own rules — the one expression that had already rotted once, and that round 4’s fix re-pinned — is now a list rather than a count. A list cannot disagree with its own contents.

7 · The gate that was red for four rounds while being called green

Round 5 found something unrelated to numbers and worse than any of them: a required CI check had been failing for four rounds, and the session had been reporting CI as green.

The cause is two grammars for one concern:

SourceSays a review gap is recorded as
docs/round-header-template.md:29halves.<name> — “ran, or a string starting GAP:”
scripts/check-review-rounds.py:86-88a line-initial REVIEW GAP: <half> — <reason>

Following the documented template puts a branch in violation of the enforced gate. Every round document on this branch used the template’s form.

The second failure is the more instructive one. The gate was run — at round 1, before any round document containing a gap existed — and it returned 0. That result was then carried forward across four rounds. The claim was not invented; it was true when made, and then outlived its subject. That is a distinct failure from asserting something unchecked, and harder to notice, because the check really did run and really did pass. The project’s most-recorded lesson covers it exactly: a green is a claim about the tree it ran on.

8 · What was filed, and the one finding that ranked it

Five backlog rows came out of this, all aimed at the same root cause — the decision is recorded and unfindable — and each was written with its own weakness stated, not only its case.

RowWorkThe weakness written into it
#179An ADR for the principleRead at architecture-review time, not when a number is typed
#180A pointer from the section about numbersA pointer is easy to write and easy to stop reading
#181A named term in the glossaryA term with no rule behind it is vocabulary
#182 🔴The two review-gap grammars; one wins, the loser is deleted, not deprecated—
#183The spine says thirteen schema gates in one row and fifteen in another—

Verified on master: docs/dev-process.md:142 reads “all THIRTEEN schema gates”; docs/dev-process.md:163 reads “the fifteen schema gates, in CI”.

#183 is worth more as evidence than as work, and that is why it was filed rather than quietly fixed. Three candidates all targeted the same cause and nothing distinguished them. #183 does: nobody writing a row in the spine document is reading the section about qualifying numbers, so #180’s pointer would never have reached it. Only an ADR — which the Phase 6 gate obliges a reviewer to read — catches that class. The ranking now rests on a demonstrated hit rather than on preference.

It is also a live instance of the principle itself, sitting in the most-read document in the repository. Its fix is written as remove the count, do not correct it — because correcting re-pins a figure that will rot again, which is exactly the move round 5 caught round 4’s fix making.

9 · What it cost, and whether it was worth it

Six rounds is far past the one round the decision procedure assigned. Measured from the GitHub Actions API across two successful runs of the required job:

StepRun ARun BShare
Mutation sweep554s542s~81%
Unit + component tests (2,892 cases)27s26s~4%
Everything else (typecheck, installs, ~30 guards)~99s~105s~15%
verify total680s673s
schema-gates (concurrent workflow)103s—0 wall clock

The sweep dominates because it does something different in kind from a test suite. Each mutation edits a delivered script and re-runs that script’s entire self-test in a fresh Python interpreter (scripts/check-plan-code.py:501). With 1,030 mutations, that is roughly 87,600 case-executions against the unit suite’s 2,892 — about 30× the work, at 538 ms per mutation versus 9.3 ms per test case.

That estimate carries its method, per the rule this PR adopts. 87,600 is not a measurement. It joins each mutation manifest’s entry count to the case count each script declares in its own docstring, matched by a regex that resolved 941 of 1,030 mutations. The remaining 89 had no count the pattern could find, so the true figure is somewhat higher.

The process isolation is the cost and also the point. A mutation’s claim is “this guard would go red if its subject broke”, and proving it needs the mutated code loaded fresh — a shared interpreter is precisely how a mutation gets masked. The project already records paying for a related mistake: a control must be run twice, because a tree that goes bad partway makes every later suite exit non-zero, recorded as a catch indistinguishably from a real one.

Was six rounds worth it? An honest split:

  • Yes for rounds 4–6. They produced the shape invariant, and found a required CI gate that had been red for four rounds under a green report. Neither was reachable by more care in rounds 1–3.
  • No for rounds 2–3 as they were spent. Each corrected a real defect and neither could terminate, because the principle that would have ended them existed and was unreachable from where the work was happening. That is the expense the five filed rows exist to prevent recurring.
