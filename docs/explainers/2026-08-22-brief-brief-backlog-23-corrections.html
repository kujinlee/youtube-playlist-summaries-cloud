The decision

Because corrections are local-only today, "fix #23" could mean three different sizes of thing. They are not increments of each other in cost — (b) and (c) touch the same files, so doing (b) first means opening the cloud path twice.

(a) Representation only {from,to} pairs replacing free-form English, applied deterministically, still only on the local regenerate path. Kills the whole-document rewrite and the second Gemini call; makes corrections inspectable before they run. Leaves the cloud lie untouched — clause (a) of the row stays open, and §5.2.2 stays blocked.
✓ (c) Representation + corrections work everywhere — recommended As (a), plus the cloud publish path applies the pairs. This is what §5.2.2 actually requires and the only version where a cloud-generated summary can carry your corrections. Deterministic application is cheap — string replacement, no Gemini call at publish — which is precisely why it becomes affordable to do on every generation, which is the thing that has never been affordable before.
(b) Representation + make the cloud honest As (a), plus the cloud stamps the truth about corrections it did not apply. Fixes the lie without building the feature. This is the surviving half of the deferred M1, arriving somewhere coherent — but it is a waypoint on the road to (c), not a destination.

The strongest argument against (c)

It is the biggest of the three, and this is the second consecutive milestone where I have argued for the larger scope after the smaller one fell apart. M1 was chosen because it was small and it was not; choosing (c) because "the small one won't do" is the same reasoning that produced two wasted rounds. (b) is genuinely honest, genuinely smaller, and stops the row lying — which is the part that silently costs the user content.

The answer

The difference is why the scope is larger. M1 grew because its premise was wrong — the mechanism did not do what it claimed. (c) is not a correction of (a); it is (a) plus one clearly-bounded addition: call a pure string function at cloud publish. The expensive part of corrections was always the Gemini round trip, and pairs delete it. Once application is a pure function, "apply it in the cloud too" stops being a slice and becomes a line. If that turns out to be false during design, (b) is still there as the fallback — and we will have learned it in step 3, not round 2.
