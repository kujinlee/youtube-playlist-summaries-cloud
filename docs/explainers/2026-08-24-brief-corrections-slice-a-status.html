Q: can doc-only review settle this, or does it need code and its more precise tools?

Largely correct, and this session measured it. The mechanical pass that just opened files found four defects both adversarial reviewers missed — in tasks both had reviewed closely. All four are things a compiler or a test run finds in seconds: an import of @testing-library/user-event that is not a dependency, fixtures using bullets: [] against a .min(3) schema, six callers T5's signature change breaks, a fixture that is not the document the pipeline emits. Prose review has poor yield on that entire class, because none of it is visible in the artifact under review.

But the inverse is just as true, and it is why the rounds were not waste. Code would not have caught any of the expensive findings: a per-call ceiling that lets twenty calls drain the global daily cap, an invalidation that breaks live share links, a bare press booking ~6¢ for applying nothing. Those compile, pass, and cost money. Compilers find defects; only reading finds wrong intentions.

So: yes, it is time. The remaining defect classes here are the ones tsc and jest settle immediately, and the design questions that needed argument have been answered. The first task is also the cheapest possible test of that claim — T3 is a three-line guard whose red phase runs at once.
