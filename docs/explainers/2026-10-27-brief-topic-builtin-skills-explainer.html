The short answer. Claude already knows every skill in the session, with its description, and is told to use one when your task matches. So you never need a name. Say what you want in plain words, or ask outright: "is there a skill for this?". The weak link isn't your memory. It's Claude noticing a match without being asked.

1. What a skill is

A skill is a packaged set of instructions (a SKILL.md file, sometimes with scripts) for one kind of task. When it's invoked, its instructions are loaded into the conversation and Claude follows them instead of its default approach. You can invoke one by typing /name, or Claude can invoke it itself through its Skill tool.

The part that answers your question: at the start of every session Claude receives the whole list, one line per skill with its description, in a block that begins "The following skills are available for use with the Skill tool". That list is in Claude's context right now. It isn't something you have to recall.

3. How a skill gets picked

  1. You type /name. That's explicit, and always works.
  2. Claude matches your words to a description and invokes it unasked. This is the path that's meant to save you from remembering names. It is passive: it works only if Claude notices.
  3. A hook nudges at a known moment. This repo already has one: .claude/hooks/suggest-explainer.sh suggests /explain-diff when gh pr create runs. Its own header says it is "A REMINDER, NEVER A GATE — always exits 0".

Why path 2 is the weak one. Matching a task to a one-line description is the same shape of problem as matching a situation to a memory. This repo measured that for memory recall (backlog #191): keyword matching found the right memory in 3 of 20 situations, and semantic matching in 20 of 20. ⚠ That's an analogy. It measured memories, not skills, and nothing here has measured skill matching. It still suggests that "Claude will notice" isn't a guarantee.

One thing pushes path 2 harder in this session. The superpowers plugin injects an instruction at session start telling Claude to check for an applicable skill before every response. That's visible in this session's context. It makes Claude look; it doesn't make the match good.

5. How to get reminded

Three ways, in the order to try them:
  1. Ask in plain words. "Is there a skill for X?" or just describe the task. Claude has every description, so this is the most reliable lookup there is.
  2. Type / and then a word. The menu lists skills and commands. ⚠ UNVERIFIED: whether it filters on the description or only the name. Try a word from what you want to do.
  3. For a moment that keeps recurring, ask for a reminder hook, like the suggest-explainer one. It works only where the moment is something a machine can see (a command being run, a file being touched).

What a cheat sheet can and can't do. docs/available-skills.md lists every skill by source. It was generated 2026-08-29 by scripts/regen-skills-doc.py, so it's two months old and may be missing skills added since. /sync-docs regenerates it. It's good for browsing, but it doesn't remind you of anything.

The idea that would remind you every time, and its cost. A hook can run on every prompt you send (UserPromptSubmit). Matching your prompt by keywords would be weak, for the reason in §3. A hook of type "prompt", which asks a model to judge, could match by meaning. ⚠ UNVERIFIED: its cost and the delay it would add to every message. Nothing here has measured them. It's worth trying only if the three ways above keep failing you.
