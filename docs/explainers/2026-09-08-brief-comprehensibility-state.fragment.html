02 ——

What the experiment found, and what you decided

The design under test splits page-building in two: a forked agent researches and writes, the main session executes the finished page in a browser and only then hands it over. The claim was that the second half cannot be delegated. That claim was argued when this page began. It is measured now, and you have accepted the verdict.

This page shipped a defect that only execution could reveal. In light theme its body text rendered at 1.03:1 contrast — effectively invisible. The palette declared some colour tokens but not the page background, so the theme toggle flipped the text and left the background pinned to the operating system. Nothing in the source looks wrong. A fork that had also verified its own work would have reported success.
Fixed, then confirmed twice independently. The page now measures 16.47:1 body and 8.69:1 body-copy in light, 15.15:1 and 8.77:1 in dark. Computed from the built file by one participant, re-measured in Chrome by the other; they agree exactly.
A prediction failed, which is also a result. The builder expected the heading “ask” buttons to collapse into one corner. Executed, all 8 sat at 8 distinct positions and all 8 were reachable. Only running the page could show that.
The concurrency question is answered — narrowly, and the first attempt was thrown away. The test was whether a page build can run beside a code review. The first run reported a clean result over a window that contained no page write at all — the write landed 87 seconds after the review finished. It was recorded as void rather than counted. The second run placed a write inside the window and came back clean. But the honest claim is small: the detector only watches two directories inside the repository, and a page build writes to neither, so it could never have failed. It says nothing about the other ways two agents collide.

decided Your verdict, 2026-09-08. Keep the split; treat the trial as passed; verification stays with the main session. That is now the default rather than an option, and it is written into the shared procedure the four page-building skills read, so it governs the next page as well as this one.

05 ——

Findings — all six are now filed

This run turned up six things. Every one is written down, five as new backlog rows and one folded into an existing row as the evidence it had been missing. Nothing here is waiting on you.

The guard against exactly this page’s defect watches one page in five. #102 There is a check for colour-token coverage, and it reads a single generated page without saying so anywhere. Four other pages — including this kind — sit outside it, because their palette is written fresh at build time and never exists as a file the guard could read. An adversarial review corrected the fix: the enforcement point is the compose step, which already refuses other malformed input.
Reader questions were being answered five times over. #103 Five question-watchers from earlier sessions were still running against the shared question file. Sessions end; the watchers they start do not. Four were stopped by hand. The shared procedure had a sentence asserting the opposite — that watchers die with their session — and that sentence has been corrected, because it was the reason nobody checked.
Rebuilding a page produces a different page each time. #106 Five rebuilds from identical input produced five different files, each larger than the last, because the build takes part of its scaffolding from whichever page is newest — which, after the first rebuild, is itself. Since answering a reader’s question rebuilds the page, a page that gets used grows every time.
A process gate blocked this page from being built at all. #104 A sentinel armed on 2026-09-05 refused the first attempt to start the fork. The plan it named had shipped and closed three days earlier — by a stronger route than the one the gate demands. The gate can only be cleared by that one route, so a plan that ships any other way leaves its sentinel armed indefinitely.
The backlog cannot be counted mechanically. #90 Filed as evidence on the existing row rather than as a new one, because that row already said the status column was doing too many jobs — what it lacked was proof. Three parsers over the same 106 rows return 64, 62 and 51 open and disagree on 22 rows. Status cells run to 3,889 characters and are append-only, so the current verdict sits at the end: one row reads open in its first line and ✅ CLOSED in its last. That is why the headline above is a range.
A shared comment is true one token at a time and misleading as a whole. #105 The styling layer describes itself as supplying “only what nobody supplied”, which invites an author to declare part of a palette. Declaring part is exactly what produced the 1.03:1 defect — and is worse than declaring none.
Settled today · and the next one, when you want it

What you decided

Keep the split. A fork researches and writes; the main session executes the finished page and only then hands it over. The step that must stay undelegated is verification — that is what earned its keep. Recorded in the design and in the shared procedure, so it governs future pages, not just this one.

What the decision deliberately does not say

Not that every page must be forked — a small page written in one pass is fine. And not that the cost is settled forever: the benefit is context saved, and that number moves as models change. The design carries an explicit expiry note telling a future reader to re-measure before assuming today’s figures still hold, rather than treating this as permanent.
