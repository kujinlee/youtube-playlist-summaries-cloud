1What the problem actually is

scripts/check-review-decision.py decides whether another review round is owed, whether a branch has converged, and whether an architecture review is armed. It reads that evidence out of a YAML block at the top of each round document — using hand-written regular expressions.

That parser has seven recorded defects. Five of them share one shape: something absent was read as something fine. A missing findings: key parsed as a clean round, and a clean round is convergence. Two go the other way and refuse valid input.

The tool filed this against itself, and it is still true today 
$ python3 scripts/check-review-decision.py        # on review-decision-procedure
ARCHITECTURE_REVIEW — thrashing: 'parse-header' carried fix-induced findings in r6 and r7

That verdict has stood since 15 September and was never actioned. Backlog #117 is its record, and #117 does not leave the question open: “the decision is which authoring cost to pay, not whether the parser is wrong.”

It surfaced because a different spec — a soundness check for the same decision card — ran two rounds and produced three Blockings that were one defect, one layer deeper each time. All three because it was adding another hand-written reader to this same component. That spec is now parked behind this one.

7Three things I would like you to weigh

1 · Is “no fallback” right, or is it a slogan?

Keeping a YAML reader as a fallback means the parser is not deleted, the seven defect shapes stay reachable, and #117 is postponed behind a flag rather than discharged. That is my argument. The counter is that it makes the cutover riskier than it needs to be — a branch in flight goes from decidable to refusing until it converts. I chose strictness; you may reasonably not.

2 · Is the human-read falsifier enough?

~31 documents is a bounded read. But it is me reading tables generated by the component under suspicion. If you want an independent check here, say so — it changes the sizing.

3 · Is this even the right next thing?

Backlog #186 (fix_induced defined twice, disagreeing at round 1) is small and independent of this, and could go first. The argument for #117 first is that #185, #188 and the parked spec all wait on it — an argument about unblocking, not about value.

#187 stopped being optional. r2 found that deferring it, combined with the new CI refusal, would make 5 committed documents permanently red — unconvertible and refused, with no action available to anyone. Two folds of one commit, each pricing its cost against a world the other removes. So disposition widens in this PR and #187 closes as a side effect.

4 · One commit contradicted itself, and you should know the shape

§2 authorised the converter to parse because it is deleted. The cutover section — added in the same commit — made it survive, so branches in flight could run it. Both cannot be true, and the surviving one is the fact the whole design rests on.

Resolved by correcting the warrant rather than the fact: the converter survives, is never in the decision path, and therefore owes the full ratchet — self-test, declared count, mutation entries. A surviving script with a parser in it is exactly what this project's guard population is for, and the first draft would have smuggled one past by calling it temporary.
