The one thing worth your judgement

Prod is running the fix. Nothing has proven prod is running the fix.

What is observed: release v7 exists, both machines report version 7 and started, the site answers, and /dev-login is 404 as it must be. The image was built from a clean tree at the merge commit.

What is inferred, not observed: that the encoder is in the running image. There is no version or build-info endpoint to ask, so the chain is clean tree → build → release — reasoning, not a measurement.

Recommendation: ingest one Korean-titled video on the live app. It is the only observation that distinguishes "deployed" from "working", and it is the exact scenario that produced the bug.

The strongest argument against: it spends real money on a path that already has an end-to-end test proving it works, and that test drives the real ingest handler and the real serve seam — not mocks of them. Spending to re-confirm a green test is superstition.

The answer to that argument: the test proves the code is right; it ran against a local stack. Every failure this project has actually shipped lived in the gap between a correct local run and production — a prod schema eight days behind, a money guard that was inert because its fixture never worked. ~8¢ to close that gap is cheap. If you would rather not spend it, that is entirely reasonable — but then the honest status is "deployed, unverified", not "fixed".

Reconciliation — where the layers disagree with git

The backlog's severity markers are stale, and they read as alarming. Backlog #36 still opens with 🔴 and #37 with 🟠, while both of their own status cells say ✅ FIXED. The marker records severity at filing and is never downgraded on close.

Anyone scanning for red — a person, or a future session — would conclude a critical blocker is open. The true count is zero. Worth a convention: strike the marker on close, or the scan is misleading by construction.

The roadmap has no deploy tick yet. It still reads as though merging were the pending gate. Git and Fly are ahead of it — the merge landed and v7 is live. That is a documentation lag of one step, not a disagreement about fact.
