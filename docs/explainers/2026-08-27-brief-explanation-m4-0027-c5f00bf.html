1 · Background — what the system does today

The skippable version

The product turns a YouTube playlist into a set of documents. For each video it produces a summary (Markdown, written by a Gemini call that costs money) and several things derived from it — a rendered HTML doc, a PDF, per-section “dig deeper” expansions. In CONTEXT.md’s vocabulary the summary is a source-of-truth blob: if it disappears, the system must say so rather than quietly regenerate, because a regenerated summary comes back different in substance. The HTML and PDF are derived-cache blobs — free and deterministic to rebuild.

Every one of those blobs is found by deriving its storage key from a base: a serial number plus a slug from the video’s title. That is the design’s original sin, and the reason this whole milestone exists.

The problem, in one sentence

The base is built from mutable data. Rename a video and the slug changes; reconcile two sides of a sync and the serial changes. Change a base and every blob addressed through it becomes unreachable — including the paid ones.

The narrow prerequisites for this change

Three earlier decisions are load-bearing here, and none is re-opened by this PR:

DecisionWhat it settledStatus
ADR-0006A blob’s address stops moving. Artifacts become workspace-scoped, and a artifact manifest maps slot → artifact as the single source of truth for which copy is current.accepted 2026-08-24
ADR-0007Artifacts are an append-only log. A second production run creates, never replaces. The reservation protocol — six review rounds of contention machinery — is deleted.accepted 2026-08-24
ADR-0011Corrections stay per-playlist. Only artifacts are shared. Recorded because nine of eleven Blocking/High findings across five rounds came from one denormalized column.accepted 2026-08-25

All three were accepted and none had ever executed. The milestone spine put it bluntly: accepted is not implemented — the schema had never run. That sentence is what this PR falsifies.

2 · Intuition — one video, two playlists, one summary

Suppose you have two playlists, Systems Reading and Weekend Queue, and the same conference talk appears in both. Today the product treats those as unrelated: two playlists, two ingests, two paid Gemini calls, two summaries that may say different things.

A workspace is the container that makes them one. Put both playlists in a workspace and the talk’s artifacts are addressed under the workspace, not the playlist — so the summary is produced once and both playlists read it.

Before
key = playlist / 007_the-talk.md
rename the video → new key → blob lost
→
After 0027
key = <workspace>/videos/<video>/<generation>/summary.md
rename anything → key unchanged

The address is now built from three ids that never change: the workspace, the video, and an opaque generation id minted when the paid run completes. The title and the serial no longer appear in it at all.

The concept doing the work: generation

A generation is one production run of a paid artifact and everything that run produced — for a summary, both the body and the card (the tl;dr, the takeaways, the format and corrections stamps). They are inseparable by construction, so a reader can never see one run’s card describing another run’s body. Run the summary again and you get a second generation; the first is untouched. The manifest decides which one is authoritative.

What ADR-0011 changed, concretely

An earlier draft of this schema also carried each video’s corrections — the user’s edits to a summary — up onto the workspace row, so they could be shared too. That is the column that produced nine of eleven findings across five rounds.

The reason is visible in the keys. videos is keyed (playlist_id, video_id); workspace_videos is keyed (workspace_id, video_id). One video in two playlists is two rows in the first table and one row in the second. Corrections are per-playlist truth, so putting them on the workspace row means two truths racing for one slot.

Before — denormalized

workspace_videos.corrections_hash is a copy. A trigger syncs it. Two playlists disagree → the copy is whatever wrote last, and the reader compares against a value that may belong to the other playlist.

After — ADR-0011

The column is gone. workspace_videos is (workspace_id, video_id) and nothing else. The reader joins to videos for the playlist it is actually serving and compares there. One truth, read where it lives.

Measured, not argued

Removing it deleted one function and two triggers (10 triggers → 8) and seven assertion blocks from the behavioural suite. Those assertions were deleted, not retargeted — the plan’s own instruction, because “an assertion retargeted to keep it alive is how a suite ends up testing what is easy rather than what matters.” The honest count of assertions this schema makes about corrections currency is now zero, and the file says so out loud.

Six boundaries move. The asymmetries in the third column are the whole point — where the two sides may assume different things, that difference is where the defects have historically lived.

Row 6 is where I would look first

It took four attempts. Two regexes missed a call because https:// appeared earlier on the line. A hand-written scanner then desynced on a regex literal containing a quote — 240 real comment lines across 12 production files were being read as code, and the construct is live at lib/html-doc/file-response.ts:8. The fix stopped guessing and asked the TypeScript compiler. Genuine comments misread: 240 → 0.

lib/html-doc/file-response.ts:6–9 — unchanged production code; the input that broke two guards

  const cleaned = base
    .replace(/[^\x20-\x7e]/g, '_') // non-printable-ASCII → _
    .replace(/["\\/;]/g, '_')       // quote, backslash, slash, semicolon → _
    .replace(/^[.\s]+|[.\s]+$/g, ''); // trim dots and spaces

A character scanner sees the " inside that character class, decides a string has opened, and from there its idea of inside-versus-outside is inverted for the rest of the file. The compiler does not, because it has to parse this correctly to compile it.

4 · Decisions this change encodes

Decided: the schema lands inert, and the day it stops being inert is observable

Nothing in lib/ app/ worker/ components/ references any M4 relation — verified, zero matches. The schema ships as pure structure. What is new is that “inert” is no longer a claim someone re-checks by hand:

scripts/check-paid-caller-arrival.py — new; the trigger for backlog 26

#   exit 0 = DORMANT — no production caller. Backlog 26 may remain open.
#   exit 1 = FIRED   — a production caller exists. Backlog 26 must be closed FIRST.
#   exit 2 = CANNOT RUN (treat as NOT RUN, never as dormant)

Backlog 26 asks which attempt ceiling governs a paid slot — the deliberate summary_max_attempts = 1, or the inherited jobs.max_attempts = 5. It costs nothing while nothing calls the write path, and 5× the moment something does. Its trigger used to be a sentence in a table.

ADR CANDIDATE: a deferred decision’s trigger must be a command, not a sentence. Hard to reverse (it changes what “tracked” means), surprising without context, and a real trade-off — a script can only observe a proxy, where a sentence can name the true condition. Currently recorded only in the backlog row and dev-process.md’s enforcement table.

Decided: gates get their own pre-M4 database rather than refusing

When 0027 was applied locally, seven gates broke identically. Refusing was honest — and it made the fourteen-gate suite unable to be green in either phase. The alternative chosen: give the rebuild gates a database of their own, cloned from the live stack with data and rolled back with the committed rollback file.

Rejected: clone schema-only

The first draft did, and gate 1 failed with null value in column "workspace_id" — 01_workspaces.sql derives workspaces from profiles, and an empty clone has none. The tempting repair was to seed two synthetic profiles. That would have been a silent loss of coverage: this gate exists to verify the DDL runs against real, populated tables, and every backfill in the migration is exactly that. Cloning with data costs 5.4 s and 21 MB, measured.

ADR CANDIDATE: a gate’s subject may be manufactured, but never simplified. The manufactured base must carry the population the real subject has, or the gate quietly becomes a different gate.

Decided: `05_assert.sql` executes everywhere, but is never a migration

The behavioural suite holds an arbitrary-SQL executor (execute p_sql) and delete from profiles. If either reaches supabase/migrations/, both are queued for production. Gate 14 is the mechanical proof that they have not — and it is the gate that round 11 caught reporting green over the exact violation it exists to detect.

Decided: open the PR with the instruments imperfect

Rounds 10 and 11 produced 1 Blocking, 8 High, 8 Medium, 6 Low. None was in 0027. Every finding was in a gate, a harness or a guard. The decision was to merge the schema and treat instrument hardening as its own slice.

The strongest argument against, and the answer

Against: these instruments are what will certify M4-β against production, so weakness in them is weakness in the production gate.

Answer: 0027 is what this PR ships; merging is a human gate; M4-β is a second human gate that happens after merge. The instruments get another pass before they are pointed at production. What round 12 would review is a .mjs file with a 10-case self-test, not anything that touches data.

What that answer does not cover: rounds 10 and 11 each found something serious in exactly this kind of code. Predicting that round 12 finds nothing would be ignoring the evidence this PR is built on.

5 · The review cascade, and why it stopped

This branch has a shape worth seeing rather than reading: each fix round caused the next round’s worst finding. portable-practices §12 predicts it; here it happened twice in one evening.

r10 H2
Fix: gate 14 passed over zero input
An unmatched glob fed the gate nothing and it reported green. Added shopt -s nullglob, a corpus floor — and set -uo pipefail.
→ r11 B1
Caused: gate 14 green over the violation itself Blocking
grep -q exits on first match; the producer dies of SIGPIPE 141; pipefail reports the producer; ! inverts it to success. Measured 8/8 false-green with pipefail, 8/8 correct without. A full 05_assert.sql appended to 0027 passed.
r10 H4
Fix: a // in a string hid a real call
Replaced two regexes with a hand-written character scanner tracking quotes.
→ r11 H1
Caused: a regex literal desyncs the scanner High
240 real comment lines across 12 files read as code; both directions reproduced on the live tree.
r11 fix
Stopped the sequence — by changing the question
Not a fifth scanner. scripts/ts-comment-spans.mjs asks the TypeScript compiler, which already ships here and already must know about regex literals, JSX and template interpolation. No fallback: missing node is CANNOT RUN.
And verifying that fix found one more, in the fix itself

TypeScript reports offsets in UTF-16 code units; Python counts code points. One file contains 🖼 — one code point, two UTF-16 units — so every offset after it drifted and a genuine comment two lines below was classified as code. Silent, direction-dependent, on the money path. Found by re-measuring, not by re-reading.

The general lesson the branch keeps paying for: each earlier fix asked “what did the last counter-example have that ordinary code does not?” — a question about characters, with an unbounded supply of answers. The escape was to stop proxying and ask the thing itself.
