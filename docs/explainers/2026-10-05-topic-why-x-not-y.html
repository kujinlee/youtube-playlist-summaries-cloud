What #224 actually is

It is a fork nobody wrote down. docs/adr/0014-a-guards-main-is-drivable.md asks a question about a run: does this guard’s --self-test invoke main() over a world the case constructed? The implementation, scripts/check-main-drivable.py, answers a question about source text: can any case point main at such a world? Those are not the same question. The substitution appears in no ADR, no docstring limit and no backlog row, and it was surfaced only by the scoped architecture review of 2026-10-03 — after rounds 1, 2 and 3 had already spent nineteen findings on its consequences.

Yes — it is the root cause, and you are right to point at it

Everything hard about the static rule follows from that fork, because deciding built from live over arbitrary Python expressions is undecidable in general. That is why three separate rounds each found the previous fix aimed at a spelling rather than at the rule. Round 5 measured the size of it: classify() over fourteen worlds, each the sole root= argument of a main call, returned thirteen false credits — and the only three refusals were exactly the three names a hand-curated list happened to contain.

But it is blind to the route this round’s Blocking lives on. The proposal in #224 is a dynamic half beside the static rule, never a replacement, for a stated reason: it is structurally blind to 3 of the 10 current credits, because a substitution of a module global leaves no filesystem trace. REBIND is the module-global substitution route — and B1 is a false credit on REBIND. The instrument that dissolves the class cannot see the defect round 10 found.

So why wasn’t it recommended?

Three reasons, weakest first, because the weakest is the one I led with at the time and that was a mistake:

  • The PR accrues conflicts while it waits. True, and the least important thing on this list.
  • The static guard ships either way. The dynamic half is additive. Building it does not delete check-main-drivable.py or its defects — those still need fixing, and the blind spot above means some of them can only ever be found statically.
  • #224 is a decision you own, not a task I can execute. It carries three options: (a) whether D2 gains a dynamic half at all; (b) if so, which verdict wins when the two disagree — a question the 7-vs-10 gap makes concrete today; or (c) amend ADR-0014’s wording to say source text, making the static rule the literal reading. Option (c) is not a no-op: it would be the first time this project amended an ADR’s Decision rather than superseding it, and docs/adr/ has no stated rule for doing that.

And the argument that actually carried was none of those — it was that the stop condition was unmet and round 9’s extraction had never been reviewed. Round 10 vindicated that. But vindicating the choice is not the same as the alternative being wrong, and I should have said so more plainly on the card.

What this changes going forward: it strengthens the case for doing #224 next, once this PR is closed out. Three rounds had independently pointed at it; round 10 is the fourth. The honest framing is that #224 and round 10 were never substitutes — one removes a defect class going forward, the other found a defect instance that was about to merge. 2 · Redesign or patch — and refuting the reviewer who proposed the redesign

This is the decision I would most want you to see, because the interesting part is that the reviewer was right about the defect and wrong about the fix, and taking its recommendation at face value would have broken something.

The defect, first

The guard asks whether a test case drives main() over a world the case built. One route — REBIND, where a case substitutes a global that main reads — was handing out credit it had not earned. The code is at scripts/check-main-drivable.py:1180:

if world_class(value, fn, tree, world) is LIVE:
    bound_here = {n.id for n in ast.walk(fn or value)
                  if isinstance(n, ast.Name) and isinstance(n.ctx, ast.Store)}
    if not (names & bound_here):
        return False
return True

It asks the owner of the question — world_class — what world an expression is, gets back LIVE, and then throws that answer away if any leaf of the expression is a name the case bound. I reproduced the consequences:

Substituted valuePARAM routeREBIND route
same_root(td), where same_root returns ROOTrefusedcreditedround 8's Codex Blocking, reopened
os.path.relpath(td)refusedcreditedround 8's relpath repair, voided
os.path.join('.', td)refusedcreditedround 5's ambient-literal rule, voided
os.path.join(f'.', td)refusedcreditedround 9's own f-string High, voided
os.path.abspath('sub')refusedrefusedcontrol — holds
tempfile.mkdtemp()creditedcreditedcontrol — correct both ways

And the discriminating control: drop the argument, and the credit vanishes. globals()['ROOT'] = same_root(td) earns rebind; same_root() earns nothing. One case-bound argument was the entire purchase price of the credit — even though same_root ignores that argument and hands back the world main already had.

Why the proposed fix was wrong

The reviewer's repair was: “one authoritative world verdict that no route may override — all four routes consume world_class's answer”. I measured it before implementing it, and two results refuted it:

1. A credit that must survive. _o = OTHER; globals()['ROOT'] = _o substitutes one world global for another. That is a change — main now reads a different global — and REBIND should credit it even though PARAM correctly refuses it (it is not a world the case built). The two routes legitimately disagree here. Making them share one verdict destroys that credit, and the code's own comments record it being lost once already and restored.

2. The purpose the clause claims is not the purpose it serves. Its comment says it exists to credit “a world derived FROM the live one — a modified copy”. I tested exactly that: os.path.join(ROOT, 'sub') and os.path.dirname(ROOT) are refused on both routes today. The clause does not do the job it says it does.

So the reviewer's finding was correct and its repair was too strong. This is a recurring shape here, not a one-off: round 8's reviewer also proposed a fix that was dead and wrong while its finding was sound. It is why the implementing brief said to treat every proposed fix as unverified code.

The design that went in instead

The defect is not that a second place decides the question. It is that the second place decides it through a proxy:

The rule
Proxy (before)Does a case-bound name appear anywhere in the expression text?
Property (after)Does this expression yield a different world global than the one being replaced?

The proxy fails whenever a case-bound name appears but does not reach the value — which is precisely same_root(td). This project has a commit named for the class: “A proxy for a property is not the property”.

And the strong version was already in the file, one branch up, at check-main-drivable.py:1178, handling reads of the module dictionary:

return _key is not None and _key != name

That line compares the resolved world identity to the name being replaced. The clause below it asks the same question through the weaker proxy. Meanwhile round 9's own extraction had just supplied the parts needed to generalise the strong version — _resolve_callee (:1559) and _ret_exprs (:1578) resolve a call to the expressions it hands back. So the redesign reuses existing machinery rather than adding any.

Why the warrant mattered more than the conclusion

This is the subtlest reason, and it is the one I would have lost entirely in a transcript. There are two ways to argue for deleting a clause, they reach the same conclusion, and only one survives review:

ArgumentAboutRecord in this slice
“Its mutation cannot die, so the clause does nothing”today's reachability3 deletions argued this way were reversed. One clause was dead and wrong
“A later, more general mechanism subsumes it”meaningEvery deletion argued this way held

The first is a claim about what the code currently happens to reach; the second is a claim about what it means. The redesign here is the second kind, which is why I was willing to do it at all — and why the brief told the implementer that if any part of the old clause is not subsumed, keep that part and say so.

Redesign or patch: the rule has exactly one test

Six of round 10's eleven findings were caused by round 9's own fix, which is the shape that escalates a component from fix to redesign. But the rule is emphatic that its own symptom table must not be used to decide (docs/review-method.md:198-200):

“THE SYMPTOM LIST IS A PROMPT, NOT THE TEST. There is one test, and it is this: Can a redesign remove it?”

It says so because using the list as a checklist produced a measured false escalation on 2026-08-14 — one reviewer escalated a stale type signature whose real fix was six words. Applied here, the test answers yes: a single authoritative world verdict dissolves the Blocking and the masking pair the extraction itself introduced. So the redesign was owed by the rule, not an override of it — which also means there is no override to record, the cheaper outcome.

The cost law, which is the part worth keeping

The sweep re-runs a guard's whole self-test once per mutation. So its cost is mutations × suite_time. The new guard has 163 mutations and a 30.0s self-test — and it is the first guard in the repo where both factors are large at once.

That is why the entire 85 minutes is attributable to one file, and why the three remaining options are all real work: a sharded CI matrix (needs a flag that does not exist), a ~100-minute dedicated job (a budget nobody is keeping, by backlog #217's own test), or moving the full sweep off the PR path entirely.

Why defer rather than fix it now

Two reasons, and the second is the stronger: the fix is real engineering on the harness every other guard's evidence depends on, so it needs its own review; and round 10's fold changes the mutation count, which would make every number above stale. Fixing it first meant deriving the arithmetic twice. The measurement was written into backlog #217 (docs/backlog.md:245) and committed as 5101f82c, so it is durable rather than living in this conversation.
