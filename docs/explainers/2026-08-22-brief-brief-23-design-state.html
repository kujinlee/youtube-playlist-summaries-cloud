The decision

In the unattended path, the corrected body only becomes real if the generation publishes. But promote is create-if-absent, so when the key is already occupied — the common case on a re-summarize — the worker's corrected body is discarded and the old body stays live. Stamping mdCorrectionsHash as current there would describe a document we did not write. That is backlog #22, and it is the M1 Blocking arriving by another route.

Recommendation — state it as a bounded dependency, do not solve it here

The spec says plainly: the attended path is fully honest (it writes with put and overwrites unconditionally); the unattended path's honesty is bounded by whether the generation publishes; that gap is #22 and M5 closes it by making publication a property of the generation rather than a race on one key.

The strongest argument against

It ships a known lie. In the promote-skipped case the row will still claim corrections it does not have — the precise defect #23 was filed about — so #23 would close having fixed the attended half and documented the other. A reviewer could reasonably say the item is not done.

The answer

Solving it here means gating the card on publication, and that is exactly what made M1 incoherent two rounds running: ten sibling fields stay unconditional, and deriveClassASignals falls back to processedAt regardless, so the silence never reaches the consumer. Re-importing that problem would repeat a mistake we have already paid for twice today. The honest move is a written boundary, not a second attempt at a fix that has already failed twice.
