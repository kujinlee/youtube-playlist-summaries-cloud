2. One file per ask: its whole life

An ask is a file named docs/asks/YYYY-MM-DD-<slug>.md. Its first line is the question; under it is the usual Decide: block with the options. It is OPEN until a line ## Answer appears in it, then ANSWERED. Answered files stay as the record; nothing deletes them.

Why a file per ask. Review rounds 2 to 4 kept finding new ways an answer could close the wrong question, because an answer had to name its question by a position inside one shared file. The architecture review removed that whole class: with the answer inside the question's own file, there is nothing to point at, so nothing can point wrong. Two branches that create the same file name with different text conflict in git, so two asks can never share a name.

Is section 2 — one file per ask, answer in the same file — right?

Recommended: yes. It is the architecture review's option (b), and it ended the thrashing.
