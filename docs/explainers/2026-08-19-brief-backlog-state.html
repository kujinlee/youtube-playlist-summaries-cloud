The finding that is actually worth acting on

The danger in #33 is not any function that exists today — it is that the default is wrong. Supabase grants EXECUTE to anon at CREATE time, so every future function is anon-callable unless someone remembers to revoke. Safety currently rests on each author independently adding an auth.uid() check.

That is the same shape as the marker convention this page is about: a rule that works only when read. The durable fix is a default revoke plus a ratchet that fails when a public function is anon-executable without being on an allow-list.

(b) The brief-compose.py shim defect

scripts/brief-compose.py is what builds this page. It lifts the Ask tray — the box you just typed into — verbatim from an older page, then injects a few lines of CSS to make the tray's colour names resolve against whatever palette the new page uses. One of those lines is broken:

scripts/brief-compose.py:54
--fg: var(--ink, #151b23); --bg2: var(--card, #fff); --rule: var(--rule, #d3d9e2);

Read the highlighted part literally: "set --rule to whatever --rule already is, or #d3d9e2 if it isn't set." That sounds harmless, but CSS forbids a custom property from referring to itself — the browser marks the whole thing invalid and --rule ends up with no value at all. The fallback never applies.

Measured on this page, just now

--rule computes to the empty string. The tray has four rules reading border: 1px solid var(--rule), so all four are discarded. The box you typed your question into has border-top-width: 0px, border-style: none — no border at all, where it was designed to have one.

Why it's worth a minute: it affects every page this script has ever produced, silently, and the failure is invisible — a missing border looks like a design choice, not a bug. The fix is one line: --rule: #d3d9e2;, dropping the self-reference. I worked around it here by naming my own token --line instead, which is why the rest of this page has its borders.

What I need from you: it's a repo change, so it's yours to authorise — fix it, file it as backlog #54, or both.
