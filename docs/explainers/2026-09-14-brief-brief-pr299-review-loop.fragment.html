The three findings worth remembering

r11 · Blocking

The gate could be walked past

A file held uncommitted for the reviewer, then reverted, left the compared set entirely — so it was never checked against anything. A file reviewed as GOOD and shipped as BAD passed with the gate printing “the final tree was reviewed by…”. Reproduced end to end before it was fixed.

r13 · High

The round-12 repair could not fail

Reverting the fix to its broken state left the entire mutation gate at 618 killed, 0 survivors — byte-identical to the repaired tree. The repair had no falsifier at all, on a branch whose whole thesis is that a guard must be able to fail.

r14 · High

A fail-open in the thing being shipped

git diff --name-only has rename detection on by default, so a guarded code file moved to a prose path vanished from the diff — and the gate reported “no guarded path changed” over a deleted code file. Measured with a control. This one was not in the new code; it was inherited, in two lines this branch had edited one round earlier for a different flag.

One incident, recorded rather than buried. A reviewer probing environment-variable redirection ran the test suite under an exported GIT_DIR pointed at the live worktree, and the suite's own fixture committed into the real repository — moving this branch's ref onto a scratch commit. Recovered from the reflog; nothing was lost, the work was already pushed. It turned that finding from reasoned about into demonstrated.

The two halves disagreed, and that is the useful part

Round 14 split: the Claude half returned NOT CONVERGED with a High; the Codex half returned CONVERGED with nothing at any severity. This repo has a recorded pattern for exactly this — when the halves disagree, the half reporting a finding has been right every time.

Sharper than a split verdict. One claim was tested by both halves and they reached opposite conclusions. The coordinator had written that a certain mutation was impossible to attribute. Codex tested it and confirmed the claim. The Claude half refuted it — by finding the counter-example the confirmation had missed. That is the strongest evidence on this page that the two reviewers are not redundant: same question, same tree, opposite answers, and the refutation was correct.
