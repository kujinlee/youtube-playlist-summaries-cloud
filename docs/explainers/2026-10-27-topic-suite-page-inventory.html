The finding that reframes it: three answers to "what needs me?"

The one question the whole suite exists to answer for you is what needs me? Today three surfaces answer it, from three sources, by three rules, and they disagree:

SurfaceIts answer todaySource and rule

/backlog-table, summary bar12 "need your decision"backlog rows whose gate is decision or study (gen-backlog-page.py:2052)
my chat closing table and /goal-tree"nothing needs you"my judgment, typed per turn; no file holds it (backlog #363: the goal tree is typed, not derived)

None of the three is wrong by its own rule. They are three different definitions of "needs you": an open ask in a change log, an open decision on a backlog row, and a blocker on the work in flight. Nothing in the suite says which one you should trust, or that they differ. So the design problem is not page count. It's that pages share questions without sharing a definition. That is what makes a consolidation decision possible: two pages that answer the same question by different rules are the first candidates to merge, or to have the question taken away from one of them.

The only machine-made cross-page link family in the suite is /features → /backlog-table. Everything else is a number in prose. A reader following one thread, say goal → its backlog rows → the PRs that closed them → the explainer that describes them, can make exactly one hop by clicking, from a feature node to a backlog row. The keys to make the rest exist already: every page writes backlog #N and PR #N as text, the anchors registry names goals, and explainer filenames carry a slug. Open questions for the owner

  1. "Needs you" has three definitions. Which is the one you mean: an open ask in the change log, an open decision on a backlog row, or a blocker on work in flight? And which single page should own it?
  2. Is the goal tree a page? You found it the most useful view (#363). Should it become a generated page that replaces or absorbs /work-lines, or stay a chat command?
  3. What is the unit of a "goal"? /goals uses anchors (13); /features uses feature nodes (26); the roadmap uses three programmes. Should a feature node declare its goal, so the two pages can link?
  4. When must a page be current? Rebuild on merge, on read (the server regenerates when asked), or accept a banner? Today, a merge leaves /dashboard and /goals stale.
  5. Which page is the target for each key? backlog #N → /backlog-table, PR #N → GitHub or a local PR page, a goal → /goals. With that decided, every page could link instead of mention (0 PR links today).
  6. Are brief pages snapshots or reports? If snapshots, should they stop restating counts that a generated page owns?
