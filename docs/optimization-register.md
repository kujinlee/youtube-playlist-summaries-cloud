# Optimization register

Owner, 2026-11-01 10:18: "there might be overlooked risks introduced by optimization efforts. Those risks
need to be well understood before making a decision in realistic terms. We may re-evaluate our decisions
later and if risks outweigh benefits, we need to adjust, revert or fine-tune the optimization."

And at 10:19: "re-evaluation has to be backed by evidence." So every row below names the evidence a
re-evaluation reads, and the observation that would make it adjust or revert. Never keep or revert a row on
opinion; a re-evaluation records the evidence it read.

**Labels.** MEASURED = read from a transcript, a run, a CI log or a PR body (source named). ESTIMATE = reasoned
from measured inputs. NOT MEASURED = nothing has measured it. Weights are the usage study's: input 1, cache
read 0.1, 5-minute write 1.25, 1-hour write 2, output 5 ("weighted tokens"). Nothing here is a number the
plan's own meter confirmed: the meter regression has no ratio yet (backlog #444).

**Sources.** `usage-study/report.md` (2026-10-30, whole session 10-22 to 10-30, Opus agents 369.5M weighted,
coordinator 265.5M), `compaction-study/report.md` (2026-10-30), `plugin-study/report.md` (2026-10-31), the PR
bodies named in each row, `docs/review-method.md` §0 Q4c, and `docs/backlog.md`. The three studies are
session scratch files, not committed; the figures quoted here are the copy of record.

## Re-evaluation

Three triggers. Any one opens a review of the rows it names.

1. **A ratio arrives.** `python3 ~/.claude/meter/regress.py` prints a sonnet/opus ratio for `seven_day`
   (backlog #444). Re-price rows 1, 2 and 5 with it, and decide the Opus-versus-Sonnet routing the backlog row
   describes.
2. **An incident is attributable to a row.** A slip, stall, retry or missed defect whose cause is in a row's
   "Signal" column. Open that row, record the evidence read, and apply its decision rule.
3. **A periodic review.** Proposed weekly, on the day the usage week resets; the owner can change the cadence.
   Each review reads the signal column of every row, writes one dated line per row (kept, tuned, reverted) with the
   evidence it read, and re-measures a benefit still marked ESTIMATE if a source now exists.

A re-evaluation that keeps a row on opinion, or reverts one on opinion, is not a re-evaluation. A row whose
evidence source cannot be run gets that source started first.

## How to add a row

Every new optimization gets a row here BEFORE it is adopted: what it is, the realistic benefit with MEASURED or
ESTIMATE, the realistic risk with its cost per occurrence, an observable signal and where to read it, the revert
path, and the re-evaluation rule. A row added afterwards records that it was late.
